# `src/ui`: in-pixel UI, HUD and every menu screen

Implements the contract's `GameUI`: **one screen-space `RenderLayer` (640×360, z = 100)** that is rasterised in software, in
pixels, with no DOM, no canvas 2D text and no web fonts. The Latin and Hangeul faces, the logotype, the controller pictures and
every screen are generated by code in this folder. Composited last by the renderer, so the UI is always crisp.

## Public API (`import … from '@/ui'`)

```ts
const ui = createUI(deps: UIDeps): GameUI;
showScreen(ui, 'controller', params?);          // jump to a screen (sandboxes, tests, "open Controller Check from pause")
```

`GameUI` (contract): `screen`, `layer`, `update(dt)`, `draw(hud | null)`, `drainActions(out)`, `showHud()`, `showResults(winner)`,
`showPause(open)`, `showTitle()`, `idleSeconds`.

`UIDeps` (`types.ts`):

| Field | |
|---|---|
| `input` | the `InputManager` from `@/input` |
| `titans: TitanInfo[]`, `portrait(id)` | roster data (`titanInfoFromDef(def)` builds a `TitanInfo`) and a portrait source (`renderPortrait`) |
| `stages: StageInfo[]` | for the stage picker's previews |
| `implementedTitans`, `implementedStages` | what can be played now; the rest is shown greyed out |
| `storage?`, `now?`, `newSeed?`, `version?`, `attractAfterSec?` | persistence, clocks and seeds (defaults: `localStorage`, `performance.now`, time-derived, 60 s) |
| `sound?(id: UiSoundId)` | menu sounds: wire to `audio.handle([{ t: 'ui', id }])` |

Actions the UI emits: `startMatch`, `quitToTitle`, `resume`, `rematch`, `restartRound`, `unlockAudio` and `setVolume` (both on the
first press on the boot screen, which is a real user gesture), `toggleTraining`, `setTrainingView`, `setQuality` (options), `setDummy`, `resetPositions`, `healBoth` (pause menu, training), `attractStart` / `attractStop`
(after `attractAfterSec` idle on the title). What the app must do with each is in the proposal doc and demonstrated by
`dev/ui/main.ts`.

The HUD: `ui.draw(hudState)` draws the in-match HUD from the public fighter views (`HudState`): live portrait of each titan's
remaining matter over a ghost of its starting silhouette, integrity bar, resource pips or bar, ultimate meter, round pips, clock,
frame advantage in Training, announcements (ROUND 2, FIGHT, KO).

## Screens

**Onboarding.** The title screen owns a three-page **HOW TO PLAY** (설명, `screens/howto.ts`): your body is your health, the moves with
the REAL button of the controller last touched (`input.actionLabel`), then charge / aim / ultimate meter. It opens by itself on a
first launch (`seenHowTo` in the stored settings), is skippable at any moment (Back or Start), and is item four of the title menu.
During round one of the very first match on a device (`matches` counts starts) `hint.ts` draws a compact strip with each human
player's buttons that fades out after about 16 seconds (`hintVisibility` is pure and tested).

`boot` → `title` → `mode` (difficulty, VS AI only) → `assign` (join P1/P2) → `select` (titans, both players at once) → `stage` →
`startMatch`. Also `controller` (Controller Check, reachable from title, options and pause), `options`, `pause`, `results`,
`attract`, `hud`. Pad, keyboard and mixed play all work; prompts follow the last-used device (Nintendo, Xbox, PlayStation glyphs
or keycaps), and each player navigates their own cursor on the select screen.

The Controller Check has three tabs: **Live** (a drawn pad with lit buttons, sticks, triggers, raw button and axis numbers, the
decoded hat, the actions currently held), **Remap** (press the input you want for any action; stored as raw references) and
**Tools** (calibrate, rotation wizard, deadzone, rumble test, WebHID).

## The toolkit (`pixel/`)

| File | |
|---|---|
| `canvas.ts` | `PixelCanvas`: integer-only rects, frames, lines, blits, clip, ordered dither, `fillAlpha` (a monomorphic int path: keep it that way, see Performance) |
| `font-data.ts`, `text.ts` | 5×7 body face and 3×5 micro face; `drawText`, `measureText`, `wrapText`; mixed Latin + Hangeul on one baseline |
| `hangeul.ts` | **All 11,172 syllables composed at runtime** from jamo on a 12×12 grid: layout by vowel class (vertical / horizontal / mixed) and final consonant; each jamo drawn with a stroke recipe fitted to its box |
| `logo.ts` | procedural logotype (Latin + 아득), integer-upscaled |
| `controller-art.ts` | the drawn Pro Controller, Joy-Con and keyboard pictures for the Controller Check |
| `palette.ts`, `shapes.ts` | shared ramps (hue-shifted), panels, plates, pillars, chips, vignette |

## Invariants

- Everything is integer pixel work; nothing anti-aliases. The layer keeps alpha 0 where the scenery should show through.
- **Hangeul is composed, not tabulated**: a test round-trips every syllable through `decompose`/`compose`, draws a sample of the
  whole block inside its cell with ink, and checks that distinct initials, vowels and finals give distinct bitmaps.
- Static backdrops and greyed sprites are cached (`backdrop(cv, key, build)`), so a menu frame is a blit plus text.
- The UI never reaches into the simulation: the HUD is drawn from `HudState` (public fighter views), and frame advantage is derived
  from those views (`advantage.ts`).
- Persistence (`settings.ts`) is guarded and sanitised: volumes, quality, last picks, the AI level, `seenHowTo` and the match count survive a reload; corrupt
  storage is ignored.
- `ui.update()` calls `input.pollIfStale()`: safe whether or not the app polled this frame.
- **Robust to slow frames** (software GL runs the game at 1-2 fps, and the shell's loop hands the UI a clamped ~0.1 s frame time, which
  made every fade, delay and the attract timer ten times slower than the wall clock): `update(dt)` uses the larger of the given
  time and the wall-clock time since its last update, capped at 1 s a frame (a hidden tab must not skip every fade), and the title's
  idle timer counts up to 30 s a frame. Input guards ("do not let a mashed button skip the result") use `settled(ctx, seconds)`,
  true after that time OR after 3 frames, so they never swallow input for more than a few frames.
- The results screen shows rounds won, damage dealt (the share of the foe's starting mass that is gone, `damageDealt`) and mass left,
  from `HudState`. The stage picker is driven by `implementedStages`: all five cards start their stage when they are listed.

## Performance

Measured with `npx tsx tools/ui/perf.ts` (Node, one core): HUD frame about 0.5 ms, menu frames 1-4 ms, all under the 4 ms test
budget. A regression that once pushed menus to 8-17 ms (V8 de-optimising a polymorphic `rect`) is now guarded by the perf test
in `ui.test.ts`; the fix was to keep translucent fills in a monomorphic int32 path (`fillAlpha`). In a real browser under
software rendering `e2e/ui.spec.ts` asserts under 8 ms per update+draw.

## How to test and look

```bash
npx vitest run src/ui                        # unit + flow tests (Nintendo pad, keyboard, two players, remap, HUD, perf budget)
npx tsx tools/ui/sheet.ts [scale] [names]    # every screen to .scratch/ui/*.png with real titan portraits (Node)
npx tsx tools/ui/specimen.ts                 # the fonts, Latin + Hangeul
npx tsx tools/ui/hangeul-sheet.ts            # a sheet of composed syllables
npx tsx tools/ui/logo-sheet.ts               # the logotype
npx playwright test e2e/ui.spec.ts           # real browser: flows with fake pads, screenshots to .scratch/e2e/
# with `npm run dev`:  /dev/ui/index.html?screen=select   (real input + UI + audio over a backdrop)
```

`fixtures.ts` has stand-in titans, portraits and a fake HUD state so screens can be developed without the simulation.

## Known limits

- Korean text covers the precomposed syllables; standalone jamo (ㄱ, ㅏ…) and Hanja are not drawn.
- The HUD is verified on fixture data (all six phases: intro, fight, ko, timeover, roundend, matchend) and in the sandbox, not yet against a live match (the app owns that wiring). Damage dealt is net mass removed: an accretor that regrew is under-counted.
- No touch or mouse control: the game is for a pad or a keyboard.

## Data strings must fit

`text-fit.test.ts` measures every string that comes from titan and stage DEFINITIONS (names, epithets, resources, taglines,
failure modes, blurbs) against the box the screens draw it in, for all six titans and five stages. It found one real overflow (Red
Giant's Wake at double size beside the palette; the stage screen now falls back to single size) and drove the select panel's
failure text to the micro face (the Supernova's is 221 characters: five lines, none cut). Add a titan or stage and it is checked.
